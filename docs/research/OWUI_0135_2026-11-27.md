# Open WebUI 0.13.5 on Windows: it does not start (night n° 18, 2026-11-27)

**The finding.** Open WebUI 0.13.5 (PyPI, 2026-11-25 09:47 UTC) cannot start on Windows. At import,
`open_webui/utils/machines/managed.py:48` runs

```python
RUN_DIR = Path(tempfile.mkdtemp(prefix='open-webui-', dir='/tmp'))
```

On Windows `/tmp` is `\tmp` on the current drive, which a laptop does not have. `open-webui serve` stops at
`import open_webui.main` (`main.py:153` → `routers/machines.py:35` → `utils/machines/managed.py:48`) with
`FileNotFoundError: [WinError 3] … '/tmp\\open-webui-…'`. Every Windows client would show *keeps exiting*.

- **Reproduced** with a clean venv (`py -3.12 -m venv`, `pip install open-webui==0.13.5`, 3½ minutes) started as a dev
  client starts it (`open-webui serve --host 127.0.0.1 --port …`, the env `buildSidecarEnv` builds), with `TMPDIR`, `TMP`
  and `TEMP` all Windows paths: the module passes `dir='/tmp'` itself. No `C:\tmp` here.
- **Upstream `main`** still has the line (read 2026-11-27 ~02:45, the file's last commit `0f71ee15a`, 2026-11-24).
  Nothing was posted upstream (CLAUDE.md: a session never posts to another project).
- **Not done:** creating `C:\tmp` to get past it. It would be a fix of Open WebUI's internals from outside, and a change
  to the computer outside the session's folder. It would not be one for people's laptops either.
- 0.13.3, our pin, starts: the machines module arrived after it (0.13.5's notes: *Terminal connections are now called
  Machines*). 0.13.4 was not tried tonight.

**So:** the pin stays 0.13.3. BLENDER_TOOLS_ENV_PLAN's step 4 (the bump) waits for an Open WebUI release that starts on
Windows. A session checks each new release's `managed.py` (or starts it) first.

## What 0.13.4 and 0.13.5 change for us (the `docs` explorer, 2026-11-27)

The explorer could quote at most 125 characters at a time, so these are excerpts, to be read again in the source at
the real bump.

- **0.13.4** removes Direct Connections and Direct Integrations (Tether replaces them): why the Blender tools moved to
  env tonight (BLENDER_TOOLS_ENV_PLAN). Image settings become connections at the first start (we set no image env).
- **0.13.5:**
  - **A database migration:** "stores each chat message separately, so upgrading converts the history in your existing
    database"; back up first. The client's copy of `webui.db` before a new version's first start
    (`sidecar.ts` `keepDbBeforeEngine`) and OWUI_START_PLAN's rule (never kill Open WebUI during its start) matter
    here. The conversion's time on a large folder is to measure.
  - **The API** returns a chat's details without repeating its messages; read `chat.history`.
  - **Terminal connections are renamed Machines.**
  - **Security:** "Update Open WebUI deployments to 0.13.5 promptly", with no CVE or GHSA id published yet.
  - **The connection editor** defaults OpenAI's own address to the Responses API. It is not said whether an env-set
    `OPENAI_API_BASE_URL` is touched: to check at the bump, a chat through a farm (LiteLLM serves chat completions).
  - **New settings:** `TOOL_SEARCH_LIST_TOOLS` (tools discovered on demand) and `TOOL_OUTPUT_MAX_CHARS`. Both are to
    read at the bump, since they may change what a model is offered.
- **Not named in either release:** `TOOL_SERVER_CONNECTIONS`, `WEBUI_AUTH`, `DEFAULT_MODEL*`, `RAG_SYSTEM_CONTEXT`,
  `RAG_FULL_CONTEXT`, the document loader, audio, web search, `HF_HUB_OFFLINE`, `RAG_EMBEDDING_*`, the user-settings
  and auth endpoints, `/api/chat/completions`' `tool_ids` and `chat_id`.
