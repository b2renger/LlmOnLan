# Qwen Code: what LlmOnLan could borrow (2026-11-14)

The owner asked (2026-11-14): "a detailed look at https://github.com/QwenLM/qwen-code … what can be borrowed and
implemented in our system". A read-only explorer mapped the repository (README, docs/, CHANGELOG, `packages/core`
sources, through a summarising fetch: values are close, re-read the file before building on one); the comparison with
our code was checked in this repo. **Nothing here is approved work**: each idea below is a proposal for the plans.

## What it is

- **Qwen Code** (`@qwen-code/qwen-code`, CLI `qwen`): the Qwen team's terminal coding agent, **Apache-2.0**, first
  forked from Google's Gemini CLI v0.8.2, no longer synced with it. Very active: 0.26.6 → 0.27.2 between 2026-11-02
  and 11-10, about 30k stars. Node ≥ 22.
- `packages/core` holds the agent loop (`core/agent-loop.ts`), the model providers (an OpenAI-compatible client with
  `baseURL`, `timeout`, `maxRetries`; vLLM, Ollama and LM Studio are documented local targets; llama.cpp is not
  named), the tools, permissions, sessions, memory and telemetry. `packages/cli` is the TUI, headless mode and
  `qwen serve`. There are TypeScript, Python and Java SDKs, a VS Code companion, JetBrains and Zed (ACP).

## Where it sits against our pieces

| Our piece | Today | What Qwen Code has |

| The farm | — | Nothing farm-side: it is a client |

## What is worth borrowing, best first

1. **A measured trial of Qwen Code as LOL Vibe's coding agent, beside dsh** (**M**, after the class). It speaks to
   our farm natively (an OpenAI-compatible base URL), is written for the models our farm serves, has an SDK shaped
   like the one `studio.ts` drives, and has the controls a classroom needs per run (wall time, tool calls, turns).
   The test that decides: `docs/spike/ide/run.js`'s tasks against dsh's numbers on the same farm and model
   (RESULTS: Qwen3.6 7–11/15, Qwen3.8 12–13/15). **Conditions, all checked in its docs:**
   - **Its usage statistics are ON by default** and post once a minute to Alibaba Cloud
     (`gb4w8c3ygj-default-sea.rum.aliyuncs.com`: the model, the base URL, the prompt's length; not its text).
     Our privacy boundary forbids that: `QWEN_USAGE_STATISTICS_ENABLED=false` (or `privacy.usageStatisticsEnabled:
     false`) in the env we hand it, as `DSH_TELEMETRY_DISABLED=1` today, and checked on the wire.
   - **Its context defaults assume big windows** (`tokenLimits.ts`: 200k input by default, 256k–1M for Qwen names;
     compression at 85 % with a 20,000-token summary reserve and a 13,000-token buffer): on our 32k–64k windows it
     must be told the window (`model.generationConfig.contextWindowSize`), or it compresses too late, as dsh did
     before our patch.
   - **Its sandbox does not cover Windows** (bubblewrap/landlock on Linux, Docker/Podman, macOS Seatbelt): our own
     confinement in `studio.ts` stays.
   - Auto-memory is on by default (`~/.qwen/…`): it must be pointed inside the person's data folder (invariant 3)
     or turned off.
2. **Loop detection in the Computer's Agent box** (**S**). Qwen Code stops a run on deterministic patterns, no model
   needed: the same call 5 times in a row, a call alternating with another (ABAB) 3 times, the same file read 8 times
   in 15 calls, the same thought 3 times. Our box spends its 12 steps instead and ends "out of steps". Two of those
   rules (the same call twice in a row; ABAB) fit in a few lines of `agent.mjs` with one unit test, and tell the
   student *why* it stopped.
3. **Never write from a cut tool call** (**S**, to check first). Qwen Code marks a tool call whose JSON arguments were
   repaired (a stream cut mid-string) so a file write refuses it (`incomplete-tool-call-args.ts`). Worth checking what
   dsh and our Agent box do with a `finish_reason: length` mid-call (the Computer already fails a code answer cut off
   at `max_tokens`: `ask.mjs`).
4. **Per-model tool-call examples** (**S**, research). Its system prompt shows tool calls in the style each model was
   trained on (`prompts.ts` `getToolCallExamples`: XML `<function=…>` for qwen-coder, JSON otherwise; override
   `QWEN_CODE_TOOL_CALL_STYLE`). The Agent box's prompt is one style for every model; a measurement on Qwen3.6/3.8
   would say whether it matters.
5. **Plan mode for students** (idea for the owner). Its approval modes include *plan* (no edits, no shell: the agent
   proposes, the person approves) — a teaching mode where a student reads the plan before anything changes.

## Not to borrow

- Its telemetry (above), and anything that sends to a cloud by default (its web search, image generation and the
  Alibaba providers): local only.
- Its whole-CLI Docker/Podman sandbox: not on students' laptops.
- Its memory files in the user's home folder: data stays in the chosen data folder.
- Re-implementing what Open WebUI already does (chat, RAG): CLAUDE.md.

## Not read

`providers/all-providers.ts`, `utils/editHelper` (its fuzzy edit correction), the text of its loop-protection
reminders, the write guard in `coreToolScheduler`, its default for Qwen thinking (`enable_thinking`), and whether its
sandbox is on by default. A trial (item 1) reads them first.
