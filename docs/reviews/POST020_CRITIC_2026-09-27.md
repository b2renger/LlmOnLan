## BLOCKER

### B1: while a person has the outputs armed, an MCP tool can still edit the graph, so a model retargets or starts live sends

`shell/renderer/chat/computer/mcp-tools.mjs:89-118` (add_box, connect_boxes, set_box), `:76-84` (open_graph,
new_graph). Only `run_graph` (`:121-122`) checks `outputsDoor().armed()`.

The guarantee in the file header, *"a model can never make a Send box talk to a real device"*, does not hold.
The pieces are:

- `outputs.ts:37-42,213`: arming is one global boolean. It is not tied to the targets that were listed when a
  person armed.
- `runbar.mjs:563`: the page disarms only when the open graph's id changes. Editing the armed graph, or hiding the
  Computer to chat in Open WebUI, leaves the outputs armed.
- `model.mjs:430-438` (`setSettings`) merges any settings patch.
- `send.mjs:173`: a Send box reads its settings at run time.
- `trigger.mjs:99-116`: a Trigger box starts runs by itself whenever the outputs are armed and the Computer is shown.

**How it fails:**
1. A person arms the outputs for a graph that has a Send box (DMX, or USB to a board).
2. They switch to Open WebUI, with the Computer tool on in that chat, and ask the model something. A web-search
   result can also steer the model here.
3. The model calls `set_box` on the Send box and changes `host`/`url`/`serialPort`/`topic`. It can also
   `add_box` a Trigger box with `{source:'schedule', every:2, perHour:3600}` and wire it to the Send box.
4. The person switches back. The outputs are still armed, so the Trigger fires, or the person's next ▶ fires.
5. The Send box transmits to a target that was never in the arming list. No MCP call was a "run".

Open WebUI only passes this tool when a person enabled it for the chat (`middleware.py` reads `tool_ids` from
the request), so both switches must be on. That is exactly the situation the header promises to handle.

**Smallest fix:** in `runTool`, check armed once for every tool that changes something:

```js
const MUTATES = new Set(['open_graph', 'new_graph', 'add_box', 'connect_boxes', 'set_box', 'run_graph']);
if (MUTATES.has(name)) { const d = outputsDoor(); if (d && await d.armed()) return no('The outputs are armed: only a person may change or run a graph now.'); }
```

Keep the read-only tools (`list_graphs`, `read_graph`, `list_box_types`) open. Also add one unit case: armed plus
set_box must be refused.

## SHOULD

### S1: MCP writes the settings that only a person may set (Sound box Listen, the USB board)

`mcp-tools.mjs:99,116` pass the model's `settings` straight to `setSettings`.

- **Listen.** `serialize.mjs:200-204` removes `listen` on import, because *"only a person on THIS machine turns it
  on"* (critic P1P2 S9). MCP does not remove it.
  - Scenario: `open_graph` (a graph whose Sound box holds a recording) → `set_box {listen:true}` → `run_graph`.
    `audio.mjs:582-596` sends the recording to the farm's speech to text, and the transcript returns to the model.
  - This breaks CLAUDE.md's rule "never sent … a Sound box's recording unless its Listen switch is on"; here a model
    turned it on.
- **Board.** `set_box {transport:'serial', serialPort:'usb:1a86:7523'}` on a Receive box makes it open that
  device as soon as the box repaints. See S2.

**Smallest fix:** in `add_box` and `set_box`, copy the patch and delete `listen` when the box is an `audio` box,
and `serialPort`/`serialLabel` when it is a `send` or `receive` box. This mirrors `serialize.mjs`.

**For the owner, not a code fix:** over MCP a model also types Fetch's `url` and the Agent's `hosts`. With the tool
on, a steered model can GET any non-loopback LAN address (router, NAS, a Tasmota that acts on GET), read the reply
through `run_graph`, and send it out in a second Fetch URL. CLAUDE.md's data-flow section says these are
addresses "a person typed" or "a person listed". Either refuse those two keys over MCP as well, or change the doc.

### S2: every USB-serial device is pre-granted, so a shared graph opens a board nobody picked on this machine

`shell/src/main/serial.ts:33`: `setDevicePermissionHandler((d) => d.deviceType === 'serial')`.

Electron's docs say this handler *"provide[s] default permissioning to devices without first calling
navigator.serial.requestPort"*. So `getPorts()` returns every serial port on the computer.

- `net/serial.mjs:98-117` (`findPort`/`ensureOpen`) opens whatever port matches the `usb:vid:pid` in the box's
  settings.
- `receive.mjs:140-142,159` calls it when the box *renders*.
- **How it fails:** someone opens a graph that was handed to them (or a model edits one, S1). Its Receive box names
  `usb:1a86:7523`, the CH340 chip used by many Arduino clones and 3D-printer boards. The port opens at once. There
  is no pick and no arming, because input is not gated.
- Opening a port typically toggles DTR, which resets Arduino-class boards. A printer printing from its SD card
  over that cable is reset.
- The comment says "the person still picks one per box". Nothing enforces it.

**Related:** the arming list shows the free-text `serialLabel` (`send.mjs:92`), not the identity. An imported graph
can label a CNC's port "LED strip".

**Smallest fix:** delete the `setDevicePermissionHandler` line.
- Electron's default keeps a port a person picked for the lifetime of the WebContents. That covers reloads, which
  was the stated reason for the handler.
- After a restart, the person picks again.
- In `targetsIn`, show `serialLabel (serialPort)`.

### S3: the Agent's exact-host allowlist does not survive a redirect

`graph/parts/agent.mjs:211-214` checks only the first URL. `src/main/io.ts:154-157` then follows up to 5
redirects to **any** non-local host.

- CLAUDE.md: "the listed hosts are the boundary".
- **How it fails:** a person lists `data.gouv.fr`. The model, or a fetched page steering it, calls
  `fetch https://www.data.gouv.fr/fr/datasets/r/<id>`. That address redirects to the file's producer URL, which
  can be anywhere, and anyone can publish a resource there. Any listed host with an open redirect
  (`/redirect?to=…`) takes a URL the model built, with data from its inputs, to any host. The reply then goes back
  into the model's context.
- The Open data box has the same pattern (`opendata.mjs:130-135`). It is lower risk because its addresses are
  derived from data.gouv.fr's own answers.

**Smallest fix:**
- **Quick:** after `door.get`, refuse the result when `new URL(r.url).host` is not in `hosts`. The model never
  reads it, but that GET has already been sent.
- **Proper:** give the fetch IPC an optional host allowlist. `fetchText` already re-runs `checkUrl` on every hop,
  so it can refuse the hop before sending it.

### S4: the new permission check handler in the client window's session grants everything, to every frame

This answers focus item 2. `serial.ts:29`: `ses.setPermissionCheckHandler(() => true)`, in the main window's session.

- It is not scoped by permission or by origin. The opaque-origin sandbox guest, which runs model-written and
  imported code, is a frame of that same session.
- For most permissions this equals Electron's default when no handler is set. It differs for
  `deprecated-sync-clipboard-read`, which Electron's default refuses and this handler grants. That permission gates
  `document.execCommand('paste')`, a synchronous clipboard read.
- The window never sets `enableDeprecatedPaste`, and I could not run the app. So I have **not confirmed** that a
  guest can read the clipboard. I rate it SHOULD because the comment claims it keeps Electron's default, and it
  does not.
- HID and USB stay unreachable: the device handler refuses them, and nobody handles `select-hid-device` or
  `select-usb-device`.
- The session has no `setPermissionRequestHandler`, so every request is granted. That was already true before this
  release. The guest's `allow=""` and its CSP `connect-src 'none'` still keep serial, the camera and the network
  out of the sandbox (`sandbox/host.mjs:243-245`, `runner.html:14`).

**Smallest fix:** `ses.setPermissionCheckHandler((_wc, p) => p !== 'deprecated-sync-clipboard-read')`.
Better: `p === 'serial' ? origin === 'file:///' : <the list the window uses>`.

## NIT

- **N1: bus, password change latency.** `farm/src/commands/up.js:1250` is the only place the bus hears the
  password: the health tick, every ≥ 10 s. After `setFarmPassword` (`:2368-2386`) or Apply (`:2450`, `:2497`), open
  sessions, and new ones using the old password, still work until that tick. Fix: call
  `sendBusKey(svcById.bus.child, config.proxy.masterKey)` right after each successful restart.
- **N2: bus, MQTT replies ignore back-pressure.** `bus.js:262,283,296,302,304` (`ack`, SUBACK, UNSUBACK, PINGRESP)
  call `socket.write` directly. PUBACK is written before `rateOk` (`:278-280`).
  - A client that floods PINGREQ, or QoS-1 PUBLISH, and never reads makes the bus process buffer the replies
    without limit, and the process dies. It is its own process, so the farm survives.
  - Fix: send these through `writeOr`, or destroy the socket once `writableLength > SLOW_BYTES`.
  - Also, before CONNECT a socket holds one of the 256 MQTT slots for 10 s. On a keyed farm, someone without the
    password can keep the MQTT port full.
- **N3: bus, WebSocket hub accepts any Origin** (`bus.js:355-380`). On an open farm with the bus on, any plain-http
  page a LAN user opens can subscribe to `#` and publish to the topics boards act on. Browsers block `ws://` from
  https pages, and the LiteLLM port has the same exposure already, so this is a NIT. Optional fix: refuse an http(s)
  `Origin` whose host is not private, loopback or `.local`; keep a missing Origin, `null` and `file://`.
- **N4: OSC, a numeric password.** `bus.js:473,485`.
  - `/lol/listen # 1234` from a tool that types `1234` as an int is refused: `keyOk` requires a string.
  - Worse, 1234 becomes the reply port, because the first int argument anywhere is taken as the reply port.
  - Fix: `keyOk(m.args[1] == null ? null : String(m.args[1]))`, and take the reply port only from `args[2]`
    (or `args[1]` on an open farm).
- **N5: `mcp.ts:84-88` checks neither Host nor Origin.** The MCP spec says servers MUST validate Origin. The bearer
  already stops DNS rebinding, so this is defence in depth: refuse a `Host` other than `127.0.0.1:41995` or
  `localhost:41995`.
- **N6: MCP port squatter.** `index.ts:1019-1024` calls `setComputerMcp` before `listen` resolves. If another
  local process holds 41995 and the sidecar spawns before the listen error arrives, OWUI sends the bearer to that
  process. The window is tiny. Fix: set it inside the `.then` when `srv` is not null. The first spawn may then lack
  it, which makes the env differ once.

## Checked and holding

**MCP server**
- The token comparison uses `timingSafeEqual` and leaks only the length.
- The body is capped at 1 MB.
- It binds to loopback only.
- `run_graph` is refused while armed (see B1 for the other tools).

**Message bus: parsers and limits**
- MQTT: the remaining length is at most 4 bytes, the length is checked against 64 KB before buffering, and a
  length split across chunks still parses. The reader is bounds-checked.
- WebSocket: masking is required; a 64-bit length is capped; fragments are capped at 64 KB in total; control frames
  are FIN-only and at most 125 bytes.
- OSC: bundles nest at most 4 deep; a bad type or a short read drops the packet.
- 200 messages/s per client; a subscriber more than 1 MB behind loses messages.

**Message bus: logging, passwords and OSC writes**
- Payloads and passwords never reach the log (a test asserts it).
- A password change closes MQTT and WebSocket sessions and clears OSC listeners.
- Passwords are compared as SHA-256 digests with `timingSafeEqual`.
- The password is passed to the child through its environment, which the child deletes after reading.
- OSC writes land only under `osc/…`: `/lol/*` is swallowed and the topic is always `osc/<address>`, as the owner
  decided.

**Open data**
- Every address sits on data.gouv.fr's hosts: the host is part of each fixed address template, and the ids are
  URL-encoded or come from data.gouv.fr's own answers.

**Trigger**
- It fires only while armed and shown.
- The gap is at least 1 s and the schedule at least 2 s.
- The hourly budget is per box.

**Agent**
- At most 12 steps, and every ask goes through `meteredAsk` and counts against the Cap. Malformed steps count too.
- The run plan quotes the most generations it may use (`mostGenerations`, `topo.mjs:241-244`).
- It has no output tool.

**Sandbox**
- `allow=""` and the CSP `connect-src 'none'`: no serial and no network from a guest.
