# P1 + P2 critic — 2026-09-27

Scope: the commits after `66c9644` (P1a Fetch + Read the news, P1b Classify, the Preview's picture, P1c the OWUI 0.11.4
bump, P2 Listen + Speak). I read every file on the brief, probed `build/main/io.js` with tricky URLs and a live
loopback server (a random high port, not a farm port), read Starlette's multipart parser in the farm venv, and ran
the three allowed suites.

Test runs: `farm/test/run.js` 126 passed. `chat-unit` 1633 passed, 1 failed. `chat-lint` found 1 violation. Both
failures come from **uncommitted** P3 work in the tree (`outputs.test.mjs` needs `build/main/outputs.js`; the lint rule 5
hit is in the untracked `graph/parts/send.mjs`), not from the reviewed commits.

## Verdict

**NOT HAPPY.** One SSRF bypass in the Fetch box, verified end to end. Three medium issues: a farm boot stall, an
unauthenticated upload path in STT, and model-written numbers reaching the news chart. Each fix is small. Everything
else is in good shape.

## Must fix

**M1 (high): Fetch reaches loopback through an IPv4-mapped IPv6 literal.** `shell/src/main/io.ts:36-42`.
WHATWG `new URL` rewrites `http://[::ffff:127.0.0.1]:PORT/` to the host `[::ffff:7f00:1]`, which is hex. The
`^::ffff:(\d+\.\d+\.\d+\.\d+)$` regex only matches the dotted form, so `blockedAddress` returns false. The DNS step is
skipped because the host is an IP literal. Verified on this box: `fetchText('http://[::ffff:127.0.0.1]:<p>/secret')`
returned `{ok:true, text:'LOOPBACK SECRET from 127.0.0.1'}`. Link-local is also open: `[::ffff:169.254.169.254]`
passes, and so does `[::ffff:0.0.0.0]`, which reaches loopback on Linux and macOS. Failure scenario: a shared graph's
Fetch box reads any unauthenticated local HTTP service, such as a ComfyUI `/history` or a dev server. It can then pass
the result to the farm, to a File box, or (once P3's send box lands) to a third party. The unit test covers only the
dotted form (`shell-main.test.mjs`, `blockedAddress('::ffff:127.0.0.1')`).
Fix: replace the hand-rolled checks with `net.BlockList`, which matches mapped addresses against IPv4 rules. I checked
this on Node 24:
```ts
const BLOCKED = new net.BlockList();
BLOCKED.addSubnet('127.0.0.0', 8, 'ipv4'); BLOCKED.addSubnet('0.0.0.0', 8, 'ipv4'); BLOCKED.addSubnet('169.254.0.0', 16, 'ipv4');
BLOCKED.addAddress('::1', 'ipv6'); BLOCKED.addAddress('::', 'ipv6'); BLOCKED.addSubnet('fe80::', 10, 'ipv6');
export function blockedAddress(ip: string): boolean {
    const f = net.isIP(ip); return f === 0 ? true : BLOCKED.check(ip, f === 4 ? 'ipv4' : 'ipv6');
}
```
Add `checkUrl('http://[::ffff:127.0.0.1]/')` and `'http://[::ffff:a9fe:a9fe]/'` → `E_LOCAL` to the test.

**M2 (med): A plugin that fails to warm up stalls `lol up` for 10 minutes before the beacon starts.**
`farm/src/classify.js:119-126`, `farm/src/stt.js:115-122`, `farm/src/plugins/registry.js:163`,
`farm/src/commands/up.js:946-950`. Plugins start one after another before step 5 (the beacon). When Laya or
faster-whisper fails to load (no Hugging Face access on a closed LAN, a bad model name, an import error), the service
stays up and answers `/health` 503 `{error:…}` forever. `waitFor*` keeps polling for the full 10 minutes. The same
happens when the process crashes: `exited` is only checked after `waitReady` returns. With both plugins on, the farm is
invisible to every client for 20 minutes.
Fix, in two parts:
- In `waitForClassify`/`waitForStt`, read the body. A 503 with a non-null `error` returns `{up:false}` at once.
- In `FarmService.start`, race `waitReady` against the child's exit:
  `res = await Promise.race([this.desc.waitReady(config, this.ctx), new Promise((r) => child.once('exit', () => r({ ok: false, level: 'warn', message: `${this.label} exited during startup` })))]);`

**M3 (med): STT accepts the whole upload before it checks the key or the size, and writes audio over 1 MB to disk.**
`farm/src/pysvc/stt_server.py:73-84`. FastAPI resolves `File(None)`/`Form(None)` before the handler body runs. The
multipart body is parsed first, and Starlette spools any file over `spool_max_size = 1 MB` to a temporary file on disk
(`starlette/formparsers.py`: `SpooledTemporaryFile(max_size=self.spool_max_size)`, with no file size limit). Two
consequences:
- (a) Any LAN host, without the key, can stream gigabytes into the farm's temp directory.
- (b) A normal Listen clip over 1 MB touches the farm's disk. The service docstring says "read into memory". CLAUDE.md
  (lines 159 and the data-flow bullet) and the Listen hint say "written down and dropped, keeps nothing".

Fix: take only `request: Request`. Check the bearer first, then require
`0 < int(request.headers.get('content-length') or 0) <= MAX_BYTES + 65536` (411/413 otherwise), then
`form = await request.form(max_files=1, max_fields=3)` and `data = await form['file'].read()`. Keep the audio in RAM
with one line at import: `from starlette.formparsers import MultiPartParser; MultiPartParser.spool_max_size = MAX_BYTES + 1`.
Apply the same content-length ceiling to `classify_server.py:112` (see S3).

**M4 (med): Model-written numbers reach the news chart. Plan §3.6 says they never should.**
`shell/renderer/chat/computer/templates/read-the-news.mjs:374, 390, 400-401` (DRAW). The chart prints the model's
`title`, `subtitle` and `insight` verbatim. The prompt says "Never write a number", but nothing enforces it, and the
template's own question ("Is AI dominating?") invites "AI leads with 12 stories". Failure scenario: the model miscounts,
and a wrong figure appears on a chart whose footer says "counts by the code". That undoes the lesson the template
exists to teach.
Fix, in DRAW: `const noNum = (s) => String(s || '').replace(/[0-9][0-9.,%]*/g, '…');` and use it on `spec.title`,
`spec.subtitle` and `spec.insight`. Stricter alternative: drop any insight that contains a digit and print a
code-built sentence from `rows[0]` instead. Add one assertion in k13 that the SVG's model-text lines contain no digit.

## Should fix

**S1 (low-med): Stop does not free the farm, and the person's own re-run is told "busy with someone else".**
`classify_server.py:131-138`, `stt_server.py:90-98`. Uvicorn does not cancel a handler when the client disconnects.
After Stop, or after the client's 2-minute (Classify) or 5-minute (STT) timeout, the batch keeps the gate and the
per-IP slot until it finishes: up to 40 s for 200 items, minutes for a 10-minute clip. The next Run gets a 429. The
runner yields with `classifyErr_busy`/`audioSttErr_busy`, which say "someone else".
Fix: in Classify, predict item by item and check between items:
`if await request.is_disconnected(): return JSONResponse({"detail":"gone"}, status_code=499)`.
In STT, iterate `segments` in the thread with a `threading.Event` that the handler sets on disconnect. Also soften the
busy sentences to "busy (maybe with your previous run)".

**S2 (low): The `waiting` counter leaks on cancellation.** `classify_server.py:130-133`, `stt_server.py:89-92`.
`waiting["n"] += 1` happens before `async with gate`. If `gate.acquire()` is cancelled (a server shutdown, or a future
middleware that cancels), the decrement never runs. After `MAX_WAITING` leaks, every request that arrives while one is
running gets a 429. Fix: `queued = True` before the acquire, and in `finally: if queued: waiting["n"] -= 1`, with
`queued = False` set right after the acquire.

**S3 (low): Classify has no body-size cap.** `classify_server.py:112`. `await request.json()` reads any size. The key is
in the beacon, so any LAN host can make it parse a 1 GB JSON. Fix: reject when `content-length` is over
`MAX_ITEMS * MAX_ITEM_CHARS * 4 + 65536`.

**S4 (low): A bad `Location` makes `fetchText` throw, and the Fetch box then shows a stale copy as "offline".**
`io.ts:108`. `new URL('http://exa mple.com/', base)` throws; I verified this. The throw breaks "never throws". `ioDoor`
turns it into `E_NET`, and `fetch.mjs:125` then serves the last copy as "offline". Fix:
`try { next = new URL(loc, url).href; } catch { return fail('E_URL', String(loc)); }`.

**S5 (low): Early returns leave the response body open.** `io.ts:111-114` (`E_HTTP`, `E_TYPE`, `E_SIZE` by header, and
each redirect hop). The socket stays open until GC; for `E_TYPE` on a multi-GB file it keeps downloading into undici's
buffer. Fix: `ac.abort()` in the `finally` next to `clearTimeout`, and `await res.body?.cancel()` before `continue` on a
redirect.

**S6 (low): `FARM_PORTS` does not include STT's 8892.** `io.ts:22`. P2 added a port that P1's list does not know. Add
`8892`. Better, derive the list from the ports the active farm advertises (the ponytail comment already names this path).

**S7 (low): The comment says "never this machine", but the code only blocks loopback.** `io.ts:5`, `fetch.mjs:5`. The
machine's own LAN addresses (`os.networkInterfaces()`) are allowed, so a `0.0.0.0`-bound service is reachable at
`http://<own-ip>:<port>`. Either add those addresses to the check or reword the comments to "loopback". CLAUDE.md
already says "loopback".

**S8 (low): Stop is ignored when it arrives before playback starts.** `audio.mjs:207` and `speak.mjs:51`. If the
signal aborts during `decodeAudioData`, `addEventListener('abort')` never fires, and up to 4000 characters of speech
play in full. Fix: `if (signal && signal.aborted) return resolve({ ok: true, seconds: 0 });` before `src.start()`, and
the same check before `synth.speak(u)`.

**S9 (low): An imported graph can arrive with Listen already on.** `audio.mjs:581` reads `settings.listen` from the
file. A teacher's shared graph with Listen on sends a student's dropped recording to the farm on Run. The student never
turned the switch on, although CLAUDE.md:159 says "ONLY when a person turns on its Listen switch". Fix: reset
`listen:false` for `audio` parts in `serialize.mjs fromJson`, the way outputs will open disarmed (plan §3.5).

**S10 (low): A doc comment is misplaced.** `preview.mjs:375-385`: `svgToPng` was inserted between `drawFree`'s JSDoc
and `drawFree`, so `drawFree` lost its types. Move `svgToPng` above line 375.

**S11 (low, docs): The data-flow text does not mention the Preview's picture.** CLAUDE.md:622 and the Computer
bullet's "What leaves" list only "an Image box's pixels". Since the "Describe a picture" preset, a Preview's PNG also
goes to the farm's vision model. Add "or a Preview's picture".

**S12 (low, tests):**
- `farm/test/run.js`, the classify test: `/laya=0.3.20|torch=cpu/` is an OR (and has unescaped dots), so it passes
  with only one of the two. Use two `assert.match` calls.

- `voiceFor` (speak.mjs:31) is pure and untested.

**S13 (low, ponytail):** `net/{extract,classify,stt,tts}.mjs` now carry four copies of the same abort, timeout and

## Solid

- **Fetch design.** It runs in main behind one IPC entry point with a 2048-character argument cap. It checks both the
  literal host and every DNS answer, re-checks each redirect hop through the same `checkUrl`, and uses one timeout for
  the whole chain. It streams with a 1 MB cap and has a `{ok:false, code}` table. My probes confirmed the refusals
  for:
  - decimal, octal and hex IPv4 (`2130706433`, `0x7f.1`, `0177.0.0.1`, `127.1`);
  - `0`, `[::]` and `[::1]`;
  - percent-encoded and full-width digits;
  - `fe80::/10`;
  - credentials and non-http schemes.

  The rebinding ceiling is stated honestly. `allowLoopback` exists only in the harness `main.cjs`.
- **Fetch box.** It has no input port, so a model never picks the address. Only `E_NET`/`E_DNS`/`E_TIMEOUT` fall back
  to the last copy, and a refusal never does. It has a unit test for exactly that.
- **Classify.** The box is pure where it matters (`itemsOf`, `optionsOf`, `labelsFrom` are unit tested), reads the
  capability at run time, and degrades to "every item unsure" with no Laya, as plan §3.2 asks. The farm side is off by
  default, uses the CPU torch index, caps threads, warms before advertising, runs with `--no-access-log`, never logs a
  body, and is advertised only while healthy. The snapshot and test coverage mirror OCR.
- **Read the news.** Numbers are joined by id; COUNT does every sum; DRAW computes every coordinate; the sort and
  measure are enums with safe defaults; unknown or missing labels go to a "check these" list; every string is
  escaped. The offline snapshot makes it run on the mock farm. Only M4 breaks the rule.
- **Preview's image output.** `optionalOutput` is a one-line runner change with clear semantics. PNGs are size-capped
  against `MAX_VALUE_BYTES` and drawn on white, and the sanitised SVG goes through `<img>`, so no external fetches.
- **Speech.** Listen is a visible, persisted switch. The client caps a clip at 25 MB and 10 min, the same as the farm
  default. The error map is complete, and "busy" and "warming" yield instead of failing. Speak's own-computer voice
  sends nothing, and its length ceiling ends a missing `end` event.
- **OWUI 0.11.4.** A one-line pin, with no LOL code change (invariant #5). I checked the built sidecar's METADATA
  against the claims: `faster-whisper==1.2.1`, `onnxruntime==1.26.0` (so the darwin-x64 rewrite still finds its pin)
  and `sentence-transformers==5.5.1`. Every OWUI env name in `configBridge.ts` appears in the 0.11.4 source; the only
  misses are library or LOL-internal names (telemetry, `HF_HUB_*`, our constants). The upgrade-in-place smoke test is
  the right evidence. One wording nit: INTEGRATION_BRIEF says "only langchain-community and rapidocr left", but
  `rapidocr==3.9.2` is still a dependency, so say what "left" means.
